Cheat Sheet – Domain 1: Design Secure Architectures (30%)

IAM policies & roles

  • Policy evaluation: explicit Deny > explicit Allow > implicit Deny.
  • Identity vs resource policies: identity attached to principal, resource attached to service.
  • Permission boundaries: maximum permissions an identity can have (cap, not grant).
  • Cross-account: trust policy on role + permissions policy; or resource-based policy.
  • Federation: SAML 2.0, Web Identity (Cognito), SSO/Identity Center for enterprise.

KMS & encryption

  • CMK types: AWS managed, customer managed, AWS owned (invisible).
  • Envelope encryption: data key encrypts data, CMK encrypts data key.
  • Key policies: resource-based policy on the CMK — required for cross-account.
  • SSE-S3: AWS manages everything. SSE-KMS: audit trail via CloudTrail. SSE-C: you manage keys.
  • Rotation: automatic yearly for AWS managed; configurable for customer managed.

VPC security

  • Security groups: stateful, allow rules only, instance-level, evaluate all rules.
  • NACLs: stateless, allow + deny rules, subnet-level, rules evaluated in order.
  • VPC endpoints: Gateway (S3, DynamoDB — free) vs Interface (most services — ENI + cost).
  • PrivateLink: expose service to other VPCs without internet/peering/NAT.
  • Flow Logs: capture IP traffic metadata at VPC/subnet/ENI level.

WAF, Shield & network protection

  • WAF: Layer 7 firewall — SQL injection, XSS, rate limiting, geo-blocking.
  • Shield Standard: free DDoS protection for all AWS customers (L3/L4).
  • Shield Advanced: enhanced DDoS, cost protection, 24/7 DRT, $3000/month.
  • AWS Firewall Manager: centrally manage WAF, Shield, SG rules across accounts.
  • Network Firewall: managed VPC-level firewall for deep packet inspection.

Cognito & SSO

  • User Pools: authentication — sign-up/sign-in, MFA, hosted UI, JWT tokens.
  • Identity Pools: authorization — exchange tokens for temporary AWS credentials.
  • IAM Identity Center (SSO): single sign-on for multiple AWS accounts + apps.
  • Organizations: SCPs restrict maximum permissions for member accounts.
  • Resource Access Manager: share resources across accounts without cross-account roles.

Exam traps

  • SG is stateful (return traffic auto-allowed); NACL is stateless (must allow both).
  • S3 bucket policies are resource-based — can grant cross-account without roles.
  • KMS key policy is required — IAM policy alone won't work without key policy allowing it.
  • VPC Gateway endpoints are free; Interface endpoints cost money.
  • Cognito User Pools = auth; Identity Pools = AWS credentials (don't confuse them).

Cheat Sheet – Domain 2: Design Resilient Architectures (26%)

Multi-AZ & Auto Scaling

  • Multi-AZ RDS: synchronous standby replica, automatic failover, same region.
  • Read replicas: async replication, can be cross-region, manual promotion.
  • Aurora: 6 copies across 3 AZs, auto-failover in <30s, up to 15 read replicas.
  • ASG policies: Target Tracking (simplest), Step Scaling, Simple Scaling, Scheduled.
  • Cooldown: prevents rapid scale in/out oscillation.

ELB deep dive

  • ALB: Layer 7, HTTP/HTTPS, path/host routing, WebSocket, Lambda targets.
  • NLB: Layer 4, TCP/UDP, ultra-low latency, static IP, millions of requests/sec.
  • GWLB: Layer 3, transparent network gateway for 3rd-party appliances.
  • Cross-zone: distributes traffic evenly across all registered targets in all AZs.
  • Health checks: unhealthy targets removed; configurable interval/threshold.

Route 53 routing

  • Simple: single resource, no health checks on record.
  • Weighted: split traffic by percentage (A/B testing, gradual migration).
  • Latency: route to lowest-latency region for the user.
  • Failover: active-passive with health checks — automatic DNS failover.
  • Geolocation/Geoproximity: route by user location or bias toward a region.
  • Alias: free, native AWS integration (ELB, CloudFront, S3) — always prefer over CNAME.

S3 replication & durability

  • CRR: Cross-Region Replication — DR, compliance, lower latency access.
  • SRR: Same-Region Replication — log aggregation, live replication between accounts.
  • Versioning: required for replication; protects against accidental deletes.
  • 11 nines durability: 99.999999999% — data loss is essentially impossible.
  • S3 Object Lock: WORM model — Governance mode (admin override) vs Compliance mode (no one).

Disaster recovery strategies

  • Backup & Restore: cheapest, highest RPO/RTO (hours). S3, snapshots, AMIs.
  • Pilot Light: core services running (DB replication), scale up on disaster.
  • Warm Standby: scaled-down full environment, quick scale-up.
  • Multi-Site / Hot Standby: full production in 2+ regions, near-zero RTO.
  • RPO: how much data you can afford to lose. RTO: how fast you must recover.

Exam traps

  • Multi-AZ is for HA (automatic failover); read replicas are for performance (manual promotion).
  • Aurora Multi-AZ failover is faster than RDS Multi-AZ (~30s vs ~60-120s).
  • NLB for static IP / extreme performance; ALB for HTTP routing / Lambda.
  • Route 53 health checks work with Failover routing — not Simple routing.
  • S3 replication doesn't replicate existing objects — only new objects after enabling.

Cheat Sheet – Domain 3: Design High-Performing Architectures (24%)

CloudFront & Global Accelerator

  • CloudFront: CDN, caches at edge locations, HTTPS, OAC for S3, Lambda@Edge.
  • OAC: Origin Access Control — restrict S3 access to CloudFront only (replaces OAI).
  • Lambda@Edge: run code at edge for request/response manipulation.
  • Global Accelerator: Anycast IP, routes to optimal endpoint via AWS backbone (not caching).
  • When to use: CloudFront for cacheable content; GA for TCP/UDP, gaming, IoT, static IPs.

ElastiCache

  • Redis: complex data types, replication, persistence, pub/sub, sorted sets, Multi-AZ.
  • Memcached: simple key-value, multi-threaded, no persistence, no replication.
  • Caching strategies: Lazy Loading (cache miss → DB → cache), Write-Through (write to both).
  • Session store: store user sessions in ElastiCache for stateless application tier.
  • Use case: reduce DB reads, leaderboards (Redis sorted sets), session management.

DynamoDB performance

  • Partition key: high cardinality for even distribution — avoid hot partitions.
  • GSI: alternate partition + sort key, eventually consistent, own throughput.
  • LSI: same partition key, different sort key, must be created at table creation.
  • DAX: in-memory cache for DynamoDB — microsecond reads, transparent to app.
  • Global Tables: multi-region, active-active replication, sub-second latency.
  • Capacity: On-Demand (unpredictable) vs Provisioned (predictable, cheaper with auto-scaling).

EBS, EFS & storage performance

  • gp3: baseline 3000 IOPS, 125 MB/s — independently scale IOPS/throughput.
  • io2 Block Express: up to 256,000 IOPS — mission-critical databases.
  • st1: throughput-optimized HDD — big data, data warehouses, log processing.
  • EFS: shared NFS, multi-AZ, auto-scaling, Linux only. Performance/Throughput modes.
  • FSx for Windows: SMB protocol, AD integration. FSx for Lustre: HPC, ML training.

Lambda & serverless

  • Concurrency: reserved (guaranteed) vs provisioned (pre-warmed, no cold start).
  • Limits: 15 min timeout, 10 GB memory, 512 MB /tmp (10 GB configurable).
  • Layers: shared code/libraries across functions (up to 5 layers).
  • Destinations: async invocation success/failure routing (SQS, SNS, Lambda, EventBridge).
  • VPC access: ENI in VPC subnet — needs NAT Gateway for internet access.
  • Event sources: API Gateway, S3, DynamoDB Streams, Kinesis, SQS, EventBridge.

ECS/EKS & containers

  • Fargate: serverless containers — no EC2 management, pay per vCPU/memory.
  • EC2 launch type: you manage instances — more control, can use Spot/Reserved.
  • Task definitions: container config (image, CPU, memory, ports, env vars).
  • Service discovery: Cloud Map integration for service-to-service communication.
  • EKS: managed Kubernetes — use when you need K8s compatibility or portability.
  • App Runner: simplest container deployment — no infra config, auto-scales.

Cheat Sheet – Domain 4: Design Cost-Optimized Architectures (20%)

EC2 pricing models

  • On-Demand: pay per second, no commitment — short-term, unpredictable workloads.
  • Reserved (1yr/3yr): up to 72% discount — steady-state, predictable usage.
  • Savings Plans: flexible commitment ($/hr) — Compute SP (any instance) vs EC2 SP (specific family).
  • Spot: up to 90% discount — fault-tolerant, flexible workloads, can be interrupted.
  • Dedicated Hosts: physical server — licensing compliance (per-socket, per-core).

S3 storage tiers

  • Standard: frequently accessed, highest cost, lowest latency.
  • Standard-IA: infrequent access, lower storage cost, retrieval fee, 30-day minimum.
  • One Zone-IA: same as IA but single AZ — non-critical, reproducible data.
  • Intelligent-Tiering: auto-moves objects between tiers — no retrieval fees, monitoring cost.
  • Glacier Instant: millisecond retrieval, quarterly access pattern.
  • Glacier Flexible: minutes to hours retrieval. Deep Archive: 12-48 hours, cheapest.

Right-sizing & Compute Optimizer

  • Compute Optimizer: ML-based recommendations for EC2, ASG, Lambda, EBS.
  • Right-sizing: match instance type/size to actual utilization (CPU, memory, network).
  • Trusted Advisor: checks for idle/underutilized resources, cost optimization.
  • Cost Explorer: visualize spending, forecast future costs, identify savings.
  • Budgets: set custom budgets with alerts when thresholds are exceeded.

Data transfer costs

  • Inbound: free (data into AWS from internet).
  • Same AZ: free (private IP). Cross-AZ: ~$0.01/GB each way.
  • Same region, different service: usually free via private IP.
  • Cross-region: $0.02/GB — use replication wisely.
  • NAT Gateway: $0.045/hr + $0.045/GB processed — expensive at scale.
  • VPC endpoints: avoid NAT Gateway costs for S3/DynamoDB (Gateway endpoints are free).

Architecture cost patterns

  • Serverless: Lambda + API Gateway + DynamoDB — pay per request, zero idle cost.
  • Spot + ASG: use Spot for stateless workers, On-Demand for baseline.
  • S3 lifecycle: auto-transition to cheaper tiers as data ages.
  • Batch transform: process data in bulk vs real-time to reduce compute costs.
  • Caching: CloudFront + ElastiCache reduce origin/DB calls and data transfer.

Exam traps

  • Spot instances can be interrupted — never use for stateful or time-critical workloads.
  • Reserved Instances are regional by default; can be zonal for capacity reservation.
  • S3 Intelligent-Tiering has no retrieval fee — unlike Standard-IA/One Zone-IA.
  • NAT Gateway is expensive — use VPC Gateway endpoints for S3/DynamoDB instead.
  • Data transfer between AZs costs money — design for single-AZ when HA isn't needed.
