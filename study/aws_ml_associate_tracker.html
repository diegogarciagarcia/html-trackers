Cheat Sheet – Domain 1: Data Engineering for ML (24%)

S3 for ML data

  • Data lake foundation: store raw, processed, and feature data in S3.
  • Partitioning: organize by date/source for efficient training data retrieval.
  • Formats: Parquet/ORC for columnar analytics; CSV/JSON for raw ingestion.
  • Versioning: track dataset versions for reproducibility.
  • Lifecycle: move old training data to Glacier; expire temp artifacts.

AWS Glue for ML ETL

  • Glue ETL: serverless Spark for data transformation at scale.
  • Glue Catalog: metadata store for ML datasets and features.
  • Crawlers: auto-discover schema from raw data sources.
  • Data Quality: validate data before training (completeness, consistency).
  • Bookmarks: incremental processing for new data only.

Kinesis for streaming ML

  • Data Streams: real-time feature ingestion, replay for retraining.
  • Firehose: deliver streaming data to S3/Redshift for batch training.
  • Analytics/Flink: real-time feature computation and anomaly detection.
  • Use case: streaming inference pipelines, real-time feature stores.

EMR for ML workloads

  • Spark ML: distributed feature engineering and model training.
  • EMR Serverless: no cluster management, pay per use.
  • When to use: large-scale data processing that exceeds Glue limits.
  • Integration: reads from S3, writes features back to S3/Feature Store.

Feature engineering

  • Numerical: normalization, standardization, log transforms, binning.
  • Categorical: one-hot encoding, label encoding, target encoding.
  • Missing data: imputation (mean/median/mode), indicator columns, dropping.
  • Text: tokenization, TF-IDF, embeddings.
  • Time series: lag features, rolling windows, seasonal decomposition.

SageMaker Feature Store

  • Online store: low-latency feature retrieval for real-time inference.
  • Offline store: S3-backed for batch training and historical features.
  • Feature groups: logical grouping of related features.
  • Point-in-time queries: prevent data leakage in training.
  • Integration: works with SageMaker Pipelines and training jobs.

Cheat Sheet – Domain 2: Exploratory Data Analysis (20%)

Descriptive statistics

  • Central tendency: mean, median, mode — know when each is appropriate.
  • Spread: variance, standard deviation, IQR, range.
  • Shape: skewness (left/right), kurtosis (heavy/light tails).
  • Percentiles: quartiles, outlier detection via IQR method.
  • Correlation: Pearson (linear), Spearman (monotonic), point-biserial.

Distributions

  • Normal: bell curve, 68-95-99.7 rule, many ML algorithms assume this.
  • Binomial: binary outcomes, n trials, probability p.
  • Poisson: count of events in fixed interval.
  • Uniform: equal probability across range.
  • Log-normal: common in financial/natural data; log-transform to normalize.

Visualization

  • Histograms: distribution shape, bin selection matters.
  • Box plots: median, quartiles, outliers at a glance.
  • Scatter plots: relationships between two variables.
  • Heatmaps: correlation matrices, feature relationships.
  • QuickSight: AWS managed BI for dashboards and ML insights.

Data bias & fairness

  • Selection bias: non-representative sampling of population.
  • Measurement bias: systematic errors in data collection.
  • Label bias: inconsistent or prejudiced labeling.
  • SageMaker Clarify: detect pre-training and post-training bias.
  • Metrics: demographic parity, equalized odds, disparate impact.

Data quality for ML

  • Completeness: missing values analysis, MCAR/MAR/MNAR patterns.
  • Consistency: duplicate detection, conflicting records.
  • Validity: range checks, format validation, domain constraints.
  • Timeliness: stale data detection, freshness requirements.
  • Ground Truth: data labeling service for high-quality training labels.

Exam traps

  • Correlation ≠ causation — never assume causal relationship.
  • Outliers: don't always remove — understand domain context first.
  • Class imbalance: use SMOTE, undersampling, or class weights — not just accuracy.
  • Feature selection: high correlation between features → multicollinearity.
  • Bias detection must happen before AND after training.

Cheat Sheet – Domain 3: Modeling (26%)

SageMaker built-in algorithms

  • XGBoost: gradient boosting, tabular data, classification/regression.
  • Linear Learner: linear/logistic regression, fast baseline.
  • K-Nearest Neighbors: classification/regression, similarity-based.
  • Random Cut Forest: anomaly detection, unsupervised.
  • DeepAR: time series forecasting with RNNs.
  • BlazingText: text classification, Word2Vec embeddings.

Training & distributed training

  • Training jobs: specify instance type, data channels, hyperparameters.
  • Data parallelism: split data across GPUs, synchronize gradients.
  • Model parallelism: split model layers across GPUs for large models.
  • Spot training: up to 90% cost savings with managed checkpointing.
  • Pipe mode: stream data from S3 instead of downloading (faster start).

Hyperparameter tuning

  • Automatic Model Tuning: Bayesian optimization by default.
  • Strategies: Bayesian, random, grid, Hyperband.
  • Objective metric: define what to optimize (accuracy, F1, RMSE).
  • Warm start: reuse previous tuning job results.
  • Early stopping: terminate poorly performing trials.

Model evaluation

  • Classification: accuracy, precision, recall, F1, AUC-ROC, confusion matrix.
  • Regression: MSE, RMSE, MAE, R².
  • Cross-validation: k-fold, stratified k-fold for imbalanced data.
  • Overfitting: high train accuracy, low test accuracy → regularize, more data, dropout.
  • Underfitting: low train accuracy → more features, complex model, less regularization.

Bedrock & foundation models

  • Amazon Bedrock: managed access to foundation models (Claude, Titan, etc.).
  • RAG: Retrieval-Augmented Generation — combine LLM with knowledge base.
  • Fine-tuning: customize foundation models with domain-specific data.
  • Prompt engineering: few-shot, chain-of-thought, system prompts.
  • Guardrails: content filtering, topic denial, PII redaction.

Exam traps

  • XGBoost is almost always the answer for structured/tabular data.
  • Don't choose deep learning when data is small and tabular.
  • Regularization (L1/L2) reduces overfitting, not underfitting.
  • AUC-ROC is threshold-independent — use when threshold isn't fixed.
  • Bedrock for managed GenAI; SageMaker for custom training.

Cheat Sheet – Domain 4: ML Implementation & Operations (30%)

SageMaker Pipelines & MLOps

  • Pipelines: define ML workflows as DAGs (processing, training, evaluation, registration).
  • Model Registry: version models, approval workflows, lineage tracking.
  • CI/CD for ML: automate retraining, evaluation, deployment on new data.
  • Step types: Processing, Training, Transform, Condition, Register, Fail.
  • Integration: EventBridge triggers, Lambda steps, CodePipeline.

Deployment strategies

  • Real-time endpoints: persistent instances for low-latency inference.
  • Serverless inference: auto-scales to zero, pay per request.
  • Batch transform: process large datasets offline, no persistent endpoint.
  • A/B testing: split traffic between model variants (production variants).
  • Canary/linear: gradual traffic shifting with automatic rollback.
  • Multi-model endpoints: host multiple models on one instance to save cost.

Model monitoring

  • Model Monitor: detect data quality, model quality, bias, and feature drift.
  • Data drift: input distribution changes from training baseline.
  • Concept drift: relationship between features and target changes.
  • Baseline: create from training data, compare against live traffic.
  • Alerts: CloudWatch alarms on monitoring violations.

SageMaker Studio & infrastructure

  • Studio: IDE for ML — notebooks, experiments, pipelines, debugging.
  • Processing jobs: data processing with managed infrastructure.
  • Experiments: track and compare training runs.
  • Debugger: detect training issues (vanishing gradients, overfitting).
  • Clarify: explainability (SHAP values) and bias reports.

Cost optimization

  • Spot instances: up to 90% savings for training (with checkpointing).
  • Right-sizing: match instance type to workload (GPU vs CPU, memory).
  • Batch transform: cheaper than real-time for non-latency-sensitive workloads.
  • Multi-model endpoints: share infrastructure across models.
  • Auto-scaling: scale endpoints based on invocation metrics.
  • Savings Plans: commit to compute usage for discounts.

Exam traps

  • Model Monitor detects drift — it doesn't retrain automatically.
  • Batch transform for offline scoring, not real-time inference.
  • Multi-model endpoints save cost but add latency for cold models.
  • Canary deployment ≠ A/B testing — canary is gradual rollout, A/B is comparison.
  • Step Functions for ML orchestration when you need non-SageMaker steps.
